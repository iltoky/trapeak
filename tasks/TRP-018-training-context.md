# TRP-018 — единый контекст для сегодняшней тренировки

Статус: **Published; authenticated MCP e2e pending**

## Description

Предоставить AI единый owner-scoped контекст для выбора тренировки на сегодня. Решение должно учитывать не только питание или состояние за текущий день, но и последовательность прошлых тренировок, накопленный объём и изменение нагрузки. TRAPEAK предоставляет факты и прозрачные агрегаты; конкретную тренировку формирует подключённый AI.

Первая версия работает на уже сохранённых provider-тренировках, provider-профиле и журнале питания. Собственный профиль целей и ограничений, сон, HRV и recovery подключаются отдельными следующими задачами.

## Acceptance Criteria

- MCP предоставляет read-only tool `get_training_context` для authenticated пользователя.
- По умолчанию возвращаются 28 дней истории; допустимый диапазон — 14–56 дней.
- В контекст входят полные нормализованные метрики тренировок от новых к старым.
- Отдельно рассчитаны окна последних 7 дней, предыдущих 7 дней и всего периода.
- Для каждого окна доступны количество тренировок и дней, длительность, active duration, дистанция, калории, TSS и группировка по типу активности.
- Доступны сигналы последовательности: последняя дата, дни после последней тренировки, тренировочные дни подряд и активности за 72 часа.
- High-load signals используют только явный provider TSS с опубликованным порогом и не называются достоверной анаэробной классификацией.
- AI получает питание за последние дни с учётом переданного пользователем UTC offset.
- Отсутствие записей питания представлено как отсутствие данных, а не как нулевое потребление.
- Ответ явно сообщает, что цели, ограничения, сон, HRV и recovery пока недоступны.
- Все запросы ограничены `user_id` из проверенного Clerk token; пользовательский ID не принимается входным параметром.
- Миграция БД для первой версии не требуется.

## Release Actions

- Опубликовать версию MCP `0.8.0`.
- Обновить tool schema в подключённых AI-клиентах или открыть новый диалог после deployment.
- Проверить `get_training_context` на production account с реальной историей тренировок.
- После smoke test обновить release status на Published.

## Testing Recommendations

- Unit test: окна 7/7/28 дней и процентное изменение нагрузки.
- Unit test: последовательные тренировочные дни и несколько high-load тренировок подряд.
- Unit test: локальная дата питания при положительном и отрицательном UTC offset.
- Unit test: пустой журнал питания не превращается в `0 kcal`.
- Ownership test: tool всегда использует Clerk identity и не принимает чужой user ID.
- Проверить ограничение ответа при более чем 100 тренировках или 500 записях питания.

3. [ ] Сверить последние тренировки с `list_activities`.
4. [ ] Сверить питание за сегодня с `get_nutrition_summary`.
5. [ ] Попросить AI предложить тренировку и проверить, что он объясняет решение через предыдущие нагрузки, а не только данные за сегодня.
