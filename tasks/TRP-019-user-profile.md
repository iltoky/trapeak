# TRP-019 — User Profile и progressive onboarding

Статус: **Published; authenticated MCP e2e passed**

## Description

Добавить независимый от wearable-провайдера профиль пользователя TRAPEAK. AI заполняет его через короткую стартовую анкету, показывает процент полноты и предлагает тематические разделы для постепенного дополнения. Профиль становится частью контекста для подбора тренировки.

## Acceptance Criteria

- Профиль owner-scoped по проверенному Clerk `user_id`; пользовательский ID не принимается параметром MCP.
- Хранятся основные данные, цели, опыт и предпочтения, расписание, оборудование, питание и контекст работы. Первоначальные ручные lifestyle-поля удалены последующим срезом [TRP-021](TRP-021-profile-daily-context.md), чтобы не дублировать wearable-источники.
- Здоровье хранится отдельно структурированными полями: травмы, состояния, противопоказания и медицинские препараты.
- Для препарата доступны название, дозировка, частота, время приёма, причина, даты и пользовательский комментарий.
- AI не выводит медицинские факты и препараты из косвенного контекста и сохраняет только явно сообщённые пользователем данные.
- `get_user_profile` возвращает профиль, процент полноты, состояние onboarding и следующие тематические разделы.
- `update_user_profile` обновляет только переданные поля; пропущенные поля не изменяются, `null` очищает поле, пустой список означает явно указанное отсутствие записей.
- `not_applicable` и `prefer_not_to_answer` считаются завершённым ответом и предотвращают повторные вопросы.
- Процент взвешивает разделы, где здоровье и препараты имеют повышенный вес, и всегда называется полнотой профиля, а не health score.
- `delete_user_profile` удаляет только custom profile и не затрагивает тренировки, питание и лабораторные отчёты.
- `get_training_context` включает custom profile и явно сообщает полноту и доступность health/medication context.
- Результаты Labs остаются отдельными датированными отчётами и не копируются в Profile.
- Дата рождения и история веса уточнены последующим срезом [TRP-020](TRP-020-weight-history.md).

## Testing Recommendations

- Unit test полноты пустого, частичного и полностью отвеченного профиля.
- Проверить, что пустой список и явный отказ завершают поле, но отсутствие поля — нет.
- Проверить валидацию дозировки, дат и максимальных размеров списков.
- Ownership test для get/update/delete и включения Profile в training context.
- Не логировать профиль, препараты или другие чувствительные health-поля.
