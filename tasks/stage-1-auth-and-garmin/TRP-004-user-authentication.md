# TRP-004 — Реализовать авторизацию пользователя TRAPEAK

## Description

Реализовать выбранный в ADR способ регистрации/входа, выход, получение текущего пользователя и защиту приватной страницы. Не писать собственную криптографию или session framework.

Если используется email, ответы не должны раскрывать наличие учётной записи. Добавить разумное ограничение частоты критичных auth-запросов.

## Acceptance Criteria

- Пользователь может зарегистрироваться/войти и выйти.
- Сессия сохраняется после обновления страницы.
- Неавторизованный пользователь не открывает приватный route.
- Пользователь не получает данные другого пользователя.
- Cookies настроены безопасно для production.
- Пароли, токены, cookies и auth headers не логируются.
- Критические сценарии покрыты integration tests.

## Release Actions

Добавить `AUTH_SECRET` и настройки email/OAuth-провайдера в secrets окружения, если они выбраны.

## Testing Recommendations

Проверить session fixation, logout, истечение сессии, generic error messages и rate limiting.

## QA e2e tests

1. Успешный вход и открытие приватной страницы.
2. Logout закрывает доступ.
3. Неавторизованный запрос перенаправляется на login.
4. Сессия одного пользователя не даёт доступ к данным другого.
