# Процесс релизов

TRAPEAK использует двухэтапную схему: **подготовить релиз → отдельно выкатить релиз**.

## 1. Подготовка

1. Создать ветку `release/vX.Y.Z` от текущего production-коммита.
2. Включить только согласованные и проверенные изменения.
3. Обновить версию в `package.json` и `package-lock.json`.
4. Создать файл `docs/releases/vX.Y.Z.md` со списком изменений, проверок и известных ограничений.
5. Выполнить `typecheck`, `test` и production `build`.
6. Пометить release candidate как `Ready`, но не обновлять `main`.

## 2. Публикация

Публикация начинается только после отдельной команды владельца проекта: **«выкатываем релиз vX.Y.Z»**.

1. Ещё раз проверить, что `main` не изменился относительно базы релиза.
2. Объединить подготовленный release commit с `main` без посторонних изменений.
3. Дождаться успешного production deployment в Vercel.
4. Проверить основные публичные страницы, авторизацию и затронутые пользовательские сценарии.
5. Обновить статус release notes на `Released`, указать production commit и дату.
6. Создать Git tag `vX.Y.Z`.

Прямые рабочие коммиты в `main` вне этого процесса не используются.
