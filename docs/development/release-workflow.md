# Процесс разработки и публикации

На этапе до появления активных пользователей TRAPEAK использует **main-only continuous deployment**.

- `main` — единственная постоянная и рабочая ветка;
- каждый завершённый и проверенный коммит в `main` публикуется в production через Vercel;
- `develop`, постоянные `feature/*` и `release/*` не используются;
- отдельное подтверждение на объединение веток не требуется.

## Перед публикацией

1. Зафиксировать небольшой и понятный scope изменения.
2. Убедиться, что в рабочем дереве нет посторонних пользовательских изменений.
3. Для изменений схемы сначала подготовить и проверить идемпотентную миграцию БД.
4. Выполнить `npm run typecheck`, `npm test` и `npm run build`.
5. Обновить документацию, текущую задачу и release notes, если изменение завершает продуктовый этап.
6. Создать один осмысленный commit и отправить его напрямую в `main`.

## После публикации

1. Дождаться статуса `Ready` у production deployment в Vercel.
2. Проверить публичный сайт, авторизацию и изменённый пользовательский сценарий.
3. Для миграций выполнить безопасную read-only проверку структуры и количества записей.
4. Зафиксировать найденные ограничения и следующие задачи в документации.

## Когда использовать Preview

Preview deployment создаётся только при повышенном риске: изменение авторизации, платежей, миграция с преобразованием существующих данных или другой сценарий, который нельзя безопасно проверить локально. Это временная проверка, а не отдельная постоянная ветка.

## Возврат к staged releases

Перед подключением первых внешних пользователей процесс пересматривается. Минимальный целевой вариант: защищённый Preview/staging, production approval, rollback-план и отдельная проверка миграций до публикации.
