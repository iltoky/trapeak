# Процесс релизов

TRAPEAK использует две постоянные ветки и двухэтапную схему: **подготовить релиз → отдельно выкатить релиз**.

- `develop` — единственная рабочая ветка; в ней собирается следующий релиз;
- `main` — только фактически опубликованный production-код.

Ветки `feature/*` и `release/*` в обычном процессе не создаются.

## 1. Подготовка

1. Все согласованные изменения последовательно добавляются в `develop`.
2. Перед релизом зафиксировать scope и не добавлять в него новые задачи без отдельного решения.
3. Обновить версию в `package.json` и `package-lock.json`.
4. Создать или обновить `docs/releases/vX.Y.Z.md` со списком изменений, проверок и известных ограничений.
5. Выполнить `typecheck`, `test` и production `build`.
6. Зафиксировать проверенный commit из `develop` как release candidate, но не обновлять `main`.

## 2. Публикация

Публикация начинается только после отдельной команды владельца проекта: **«выкатываем релиз vX.Y.Z»**.

1. Ещё раз проверить актуальные состояния `develop` и `main`.
2. Объединить проверенный release candidate из `develop` с `main` без посторонних изменений.
3. Дождаться успешного production deployment в Vercel.
4. Проверить основные публичные страницы, авторизацию и затронутые пользовательские сценарии.
5. Обновить статус release notes на `Released`, указать production commit и дату.
6. Создать Git tag `vX.Y.Z`.

Прямые рабочие коммиты в `main` и дополнительные рабочие ветки вне этого процесса не используются.
