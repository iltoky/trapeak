# Internationalization

TRAPEAK supports seven interface locales:

| Locale | Public URL |
| --- | --- |
| `en` | `/en/` |
| `pt-BR` | `/pt-br/` |
| `es-419` | `/es/` |
| `id` | `/id/` |
| `vi` | `/vi/` |
| `hi` | `/hi/` |
| `bn` | `/bn/` |

English is the default and fallback locale.

## Architecture

- `lib/i18n/config.ts` is the locale registry, URL mapping, detection logic, and public-route inventory.
- `lib/i18n/ui.ts` contains authenticated UI and system copy by namespace.
- `lib/i18n/public-content.ts` contains landing, guide, use-case, legal, and SEO copy.
- `lib/i18n/server.ts` resolves the persisted locale for authenticated pages.
- `app/[locale]/[[...path]]` statically generates every localized public page and its metadata.
- `proxy.ts` redirects legacy public URLs to a locale URL. The locale cookie wins; otherwise `Accept-Language` is matched; unsupported languages fall back to English.

Translations must not be stored in React components. Add copy to the relevant typed namespace so an omitted key fails type checking.

## User preferences

`locale`, `timeZone`, and `measurementSystem` are independent profile fields. `locale` controls presentation, `timeZone` controls date boundaries, and `measurementSystem` controls display units. None of them sets the language of a ChatGPT, Claude, or other AI conversation.

The locale selector writes the `trapeak_locale` cookie immediately and, for authenticated users, persists the same value through `PATCH /api/preferences`. Time zones use IANA names. Measurements are `metric` or `imperial`.

No database migration is required: the profile is stored as JSONB and the additions are backward-compatible. Missing preferences resolve to English and metric presentation without changing existing stored values.

## SEO

All indexable public pages are statically generated for every locale. Each page supplies a localized title, description, OpenGraph metadata, canonical URL, and `hreflang` alternatives with English as `x-default`. The sitemap contains only canonical locale URLs. Planned Garmin pages remain `noindex` until the integration is available.

Do not create a translated page that reuses English marketing copy. Positioning should be adapted naturally for the market while retaining the product meaning: TRAPEAK is the personal health data layer for AI, not another AI coach.

## MCP and API contract

Stored and returned data stays language-neutral. Use stable keys and typed values such as `weightKilograms: 90`, ISO dates, and enumerations. Never return a localized sentence in place of a structured field. Tool descriptions can explain the contract in English, while the connected AI chooses the response language.

Profile-completeness section identifiers use stable keys (`basics`, `trainingAndGoals`, and so on). Provider credentials and raw provider payloads are never localized or exposed.

## Adding a locale

1. Add the BCP 47 locale, URL slug, HTML language, OpenGraph locale, and native name in `lib/i18n/config.ts`.
2. Add a complete `UiMessages` dictionary in `lib/i18n/ui.ts`.
3. Add complete public, guide, use-case, legal, and SEO content in `lib/i18n/public-content.ts`.
4. Add the Clerk localization mapping in `lib/i18n/clerk.ts`.
5. Add copy-button labels and update locale tests.
6. Run typecheck, tests, and production build; then smoke-test detection, selection, fallback, forms, long text, mobile layout, metadata, sitemap, and authentication.

Adding the eighth locale is a registry-and-content change; routing, persistence, SEO generation, and selectors require no new architecture.

## Email localization

Email producers must receive the recipient's stored locale explicitly and select a centralized template namespace. Email payload data (invitation token, expiry, categories, URLs) remains structured. When a recipient has no stored preference, use English. At present Clerk owns authentication email delivery; its supported locale is selected through the same locale mapping. Product-owned email templates must follow this contract when introduced.
