# Remote MCP

Статус: **Production private beta**

## Назначение

Remote MCP — основной интерфейс MVP TRAPEAK для AI assistants. Он предоставляет только нормализованные пользовательские данные и не заменяет dashboard аналитикой.

Production endpoint: `https://trapeak.com/mcp`.

## Аутентификация и ownership

Clerk выступает OAuth 2.1 authorization server. ChatGPT или другой MCP-клиент запускает OAuth flow, пользователь входит в TRAPEAK и подтверждает доступ. Каждый MCP request содержит Clerk-issued bearer token. Сервер проверяет token и извлекает `userId`; параметры инструментов не могут переопределить identity.

OAuth discovery endpoints:

- `/.well-known/oauth-protected-resource/mcp`;
- `/.well-known/oauth-authorization-server`.

Все SQL-запросы MCP обязательно фильтруются по проверенному `user_id`. `get_activity` дополнительно связывает внутренний activity UUID с тем же владельцем. Неавторизованный request получает RFC 9728-compatible `WWW-Authenticate` challenge.

## Контекст для сегодняшней тренировки

`get_training_context` — агрегирующий read-only tool. По умолчанию он возвращает 28 дней истории, а клиент может запросить от 14 до 56 дней. В ответ входят:

- нормализованный provider-профиль, custom Profile и полные доступные метрики предыдущих тренировок;
- нагрузка за последние 7 дней, предыдущие 7 дней и весь выбранный период;
- группировка нагрузки по типам активности и процентное изменение объёма;
- последовательность тренировочных дней, активности за 72 часа и TSS-based high-load signals;
- питание за последние 7 дней с учётом переданного UTC offset;
- явные признаки полноты custom Profile и отсутствия подключённых sleep, HRV и recovery data.

AI должен вызывать этот tool перед рекомендацией тренировки и оценивать последовательность предыдущих нагрузок. Порог `TSS >= 80` обозначает только высокую provider-нагрузку и не считается достоверной классификацией тренировки как анаэробной. Если TSS отсутствует, AI использует тип, название, длительность, пульс и порядок тренировок и сообщает об ограниченной точности.

## Profile и progressive onboarding

`get_user_profile` вызывается перед началом или продолжением анкеты. Первый шаг группирует критичные вопросы о цели, базовых параметрах, тренировочном опыте, травмах, противопоказаниях, препаратах и доступном времени. После `update_user_profile` AI сообщает процент полноты и предлагает на выбор следующие темы.

Процент является только полнотой сохранённых данных. Здоровье и препараты имеют повышенный вес, но результат не является health score. Пустой список означает явный ответ «нет», отсутствие поля — ещё не заданный вопрос, а `not_applicable` и `prefer_not_to_answer` предотвращают повторные запросы. Пропущенные поля при update не изменяются.

Препараты хранятся структурированно: название, дозировка, частота, время, причина, даты и комментарий. AI не выводит медицинские сведения из тренировок, анализов или косвенного контекста и не подменяет консультацию врача.

## Безопасное удаление

- AI сначала получает внутренний ID через соответствующий list tool, если пользователь его не указал.
- Запрос исправить, заменить или повторно загрузить данные не считается запросом на удаление.
- SQL `DELETE` всегда ограничен проверенным Clerk `user_id`; чужой или отсутствующий ID возвращает `deleted: false` без раскрытия владельца.
- `lab_results` связаны с отчётом через `ON DELETE CASCADE`.
- Dashboard использует authenticated same-origin POST и отдельное пользовательское подтверждение.

## Граница данных

MCP не возвращает:

- OAuth access/refresh tokens;
- Clerk user ID;
- Wahoo user ID и provider activity ID;
- raw provider payload;
- данные другого пользователя;
- значения, которых нет в нормализованной БД TRAPEAK.

Для связи между `list_activities` и `get_activity` используется внутренний TRAPEAK UUID.
