# Данные, конфигурация и секреты

## Переменные окружения

Переменные окружения содержат конфигурацию экземпляра TRAPEAK, общую для всех пользователей:

```env
APP_URL=
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=
CLERK_SECRET_KEY=
DATABASE_URL=
POSTGRES_URL=
TOKEN_ENCRYPTION_KEY=
WAHOO_CLIENT_ID=
WAHOO_CLIENT_SECRET=
```

Точные названия параметров каждого фитнес-провайдера необходимо сверять в его документации. В Git хранится только `.env.example` без значений. Clerk keys подключаются через Vercel Marketplace или вручную в Vercel Environment Variables.

Для PostgreSQL достаточно одной переменной: локальный стандарт `DATABASE_URL` или автоматически создаваемый интеграцией Vercel Neon `POSTGRES_URL`. Если заданы обе, приоритет имеет `DATABASE_URL`.

## Данные пользователя

Для каждого пользователя в БД хранится отдельное подключение Wahoo:

- внутренний `user_id`;
- Wahoo user identifier;
- статус подключения;
- access/refresh tokens в зашифрованном виде;
- срок действия и scopes;
- даты подключения, ошибки и отключения.

После явной синхронизации отдельно сохраняются:

- нормализованный Wahoo-профиль и исходный JSON профиля;
- завершённые тренировки с provider activity ID;
- нормализованные время, дистанция, длительность, пульс, каденс, скорость, мощность и другие доступные сводные показатели;
- исходный JSON workout record для последующего расширения нормализации;
- состояние последней синхронизации и число сохранённых тренировок.

Уникальный ключ `(user_id, provider, provider_activity_id)` делает повторную синхронизацию идемпотентной. Planned workouts без `workout_summary` не записываются как завершённые активности.

Custom Profile хранится отдельно от provider-профиля и ограничен внутренним `user_id`. JSON-документ содержит только нормализованные поля Profile: цели, расписание, предпочтения, здоровье, препараты, питание и lifestyle. Статусы `not_applicable` и `prefer_not_to_answer` хранятся отдельно от значений и используются только для progressive onboarding. Медицинские поля не логируются и не выводятся из косвенных данных; AI сохраняет их только по явной команде пользователя.

Пароль Wahoo не запрашивается и нигде не хранится. OAuth-токены нельзя хранить в переменных окружения: это динамические данные конкретных пользователей.

## Правила

- шифрование токенов выполняется на сервере;
- ключ шифрования хранится отдельно от БД;
- authorization code и токены не логируются;
- raw OAuth responses не сохраняются;
- MCP clients не получают provider tokens, raw payload, Clerk user ID или provider user ID;
- MCP activity lookup всегда ограничен `user_id`, полученным из проверенного OAuth token;
- удаление аккаунта, отключение Wahoo и удаление тренировок — разные операции.
- удаление custom Profile не удаляет тренировки, питание или лабораторные отчёты.
