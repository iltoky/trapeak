# Product Vision

## Проблема

Fitness- и health-данные распределены между wearable-платформами, описаниями питания и лабораторными документами. Пользователю трудно собрать единый контекст, а универсальный AI-ассистент не имеет безопасного структурированного доступа к нему.

## Решение

TRAPEAK подключается к fitness-провайдеру с согласия пользователя, сохраняет нормализованные тренировки и предоставляет их через MCP-интерфейс Claude и ChatGPT. По явной команде пользователя AI также может сохранять описание приёма пищи с суммарными КБЖУ и структурированные лабораторные результаты. Первым wearable-источником стал Wahoo; Garmin остаётся следующим приоритетом после получения API-доступа.

## Целевая первая аудитория

Любители бега и велоспорта, которые используют Wahoo и хотят получать контекстные ответы по тренировкам, питанию и лабораторным показателям без ручного переноса данных между сервисами.

## Идеи для будущей декомпозиции

- TRAPEAK хранит пользовательскую историю независимо от выбранного AI-провайдера.
- Данные можно вводить там, где удобнее, например голосом через ChatGPT, а анализировать и визуализировать в другом специализированном AI.
- AI может подбирать тренировку на сегодня с учётом последовательности прошлых тренировок, индивидуальной динамики нагрузки, целей и медицинских ограничений, питания, сна, восстановления и свежей субъективной оценки состояния. Отдельный паттерн — например, несколько требовательных сессий подряд — является только одним из факторов и не должен автоматически определять рекомендацию.
- Целевой onboarding: регистрация → подключение источников → один стартовый промпт → короткая анкета в AI → сохранение профиля → первый полезный результат.
- Владелец может дать другому зарегистрированному пользователю — например, тренеру или врачу — отзывный доступ только к выбранным группам данных и на ограниченный срок. Тренер может видеть тренировки и питание без лабораторных данных и препаратов; врачу можно отдельно открыть анализы и медицинский контекст. Первый срез такого доступа должен быть read-only, с аудитом обращений и без передачи общего логина.
- Позиционирование: «Записывайте там, где удобно. Анализируйте там, где лучше» и «AI меняются — ваша история остаётся».

Исторический тренировочный контекст декомпозирован в TRP-018, Profile и progressive onboarding — в TRP-019, история веса и напоминания — в TRP-020, а граница Profile/wearable — в TRP-021. Подготовка публичных материалов и SEO описана в TRP-022, переход Wahoo application из Sandbox в Production — в TRP-023, делегированный доступ — в TRP-024. Reusable-шаблон для ускорения новых интеграций остаётся отложенной идеей и сейчас не реализуется.

## Принципы

- данные принадлежат пользователю;
- минимально необходимые разрешения;
- понятное подключение и отключение;
- AI получает только данные текущего пользователя;
- write tools вызываются только после явной команды пользователя;
- AI-оценки питания сохраняются вместе с допущениями;
- лабораторные значения хранятся как переданные, без автоматической диагностики;
- исходные данные сохраняются для повторной обработки;
- рекомендации не выдаются за медицинские заключения.
