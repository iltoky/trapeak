# v0.10.0

Статус: **Implementation complete; production migration and authenticated e2e pending**

## Что добавлено

- Временный read-only доступ к данным по email без ролей.
- Четыре категории: `training`, `nutrition`, `health`, `recovery`.
- Одноразовые invitation links, accept/reject, expiry и немедленный revoke.
- Страница `/access` для выдачи grants, просмотра доступа и audit activity.
- Пять MCP read tools для работы одного получателя с несколькими спортсменами.
- Серверное редактирование health, nutrition и weight полей, если категория не выдана.

## Безопасность и rollout

- Invitation token хранится только как SHA-256 hash и привязывается к Clerk account с совпадающим primary email.
- Каждый delegated read проверяет recipient ID, status, expiry и permission на сервере и пишет audit event с OAuth client ID.
- Перед production rollout требуется migration `0010_delegated_data_access.sql`.
- Authenticated browser/MCP e2e выполняется отдельным этапом после migration и deployment.
- Отдельные OAuth client policies остаются следующим срезом; они будут только сужать human grant.
